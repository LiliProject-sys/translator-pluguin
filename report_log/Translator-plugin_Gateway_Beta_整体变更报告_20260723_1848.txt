2. 本轮修改摘要

本轮将 Translator-plugin 从纯客户端 BYOK Provider 模式扩展为“本地 Beta Gateway”模式。新增 gateway/ FastAPI 服务端，提供 /health、/v1/auth/verify、/v1/language 三个端点；新增 gateway-language-provider.js，让 Chrome 插件通过固定本地地址 http://127.0.0.1:8000 调用 Gateway；设置页新增普通用户欢迎区和测试访问码输入框，验证成功后才保存 Token 并切换 provider=gateway。

用户现在能看到的主要变化是：打开 options 页面顶部会出现“欢迎使用 Translator”和“测试访问码”输入框，以及“验证并开始使用”按钮；原有百度、Gemini、DeepSeek、Mock 配置被收进“高级设置（自带 API Key）”折叠区域。

内部架构变化是：translation-provider.js 新增 gateway Provider 注册；background.js 复用 TEST_LANGUAGE_PROVIDER 做 Gateway Token 验证；manifest.json 增加本地 Gateway host permission；服务端固定 Skill 与插件现有 Validator 通过共享 JSON fixture 对齐。

明确没有修改：content.js 主链路、vocabularyEntries 数据结构、生词保存去重规则、旧 Baidu/Gemini/DeepSeek/Mock Provider 的核心实现、manifest 版本号 1.0.1、Cloud Run 线上部署。

4. 修改后状态

修改前：普通用户必须选择 Provider 并理解 API Key。
修改后：普通用户在 options 顶部输入共享 Beta Token，点击“验证并开始使用”；验证成功后才保存 gatewayAccessToken 并自动切换 provider=gateway。

修改前：语言处理只走客户端 Provider。
修改后：provider=gateway 时，插件走 GatewayProvider，再调用本地 FastAPI Gateway；Gateway 固定服务端 Skill 和 Gemini 模型，返回现有 UI 可直接使用的数据合同。

修改前：TEST_LANGUAGE_PROVIDER 不支持候选 Token。
修改后：TEST_LANGUAGE_PROVIDER 在 provider="gateway" 时读取 message.config.gatewayAccessToken，只调用 /v1/auth/verify；验证失败不保存 Token、不覆盖旧配置、不切换 Provider、不调用 Gemini。

修改前：没有服务端输入限制。
修改后：服务端 LanguageRequest 限制 text 最大 5000 字符、contextSentence 最大 5000 字符、pageTitle 最大 300 字符、请求体最大 32 KB；Token 使用 hmac.compare_digest 恒定时间比较。

修改前：Gateway URL 不存在。
修改后：Gateway URL 唯一源码定义在 gateway-language-provider.js 的 GATEWAY_BASE_URL，当前值为 http://127.0.0.1:8000。普通用户设置页不可见、不可编辑。

修改后保持兼容：
- content.js 主链路不变；
- SAVE_VOCABULARY_ENTRY 与 GENERATE_VOCABULARY_CONTEXT_TRANSLATION Message Type 不变；
- vocabularyEntries 结构不变；
- 旧 Provider 仍可在高级设置中使用；
- manifest 版本仍是 1.0.1。

- Gateway 原样返回；

- content.js 继续用现有 selectionId/requestId 机制丢弃旧响应。

错误转换：
- Gateway HTTP/JSON 错误在 GatewayProvider 转换为现有 Provider error；
- REQUEST_CANCELLED 由 background.js 转成 status="cancelled"；
- 其他错误由 background.js 转成 status="error"。
