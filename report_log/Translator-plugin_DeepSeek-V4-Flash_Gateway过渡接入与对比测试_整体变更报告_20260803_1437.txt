五、max_tokens 最终处理

没有沿用所有请求统一 500 的策略。Gateway 调用层按业务输出结构使用三档上限：

- Word Quick：256
- Word Detail：512
- Sentence Translation：8192

Word 输出字段很少，较小上限可防止异常扩展；Sentence Translation 最长可接收 5000 字符目标文本，因此使用更高上限，降低长段落 JSON 被截断的风险。上限集中在 upstream.py，Skill 不承担 Provider 参数。

六、JSON、重试与错误映射

只有 finish_reason=stop 才进入 JSON 解析。length、content_filter、tool_calls、insufficient_system_resource、缺失状态和未知状态均转换为明确错误。

空 content 最多重试一次，两次调用共享同一个总超时截止时间。第二次仍为空返回 UPSTREAM_EMPTY_RESPONSE。Markdown code fence 不会被自动剥离，而是作为非法 JSON 拒绝。JSON 成功解析后仍必须通过原 Pydantic Schema；缺字段、额外字段和非法字段值返回 UPSTREAM_SCHEMA_INVALID。

HTTP 映射：
- 400/422：UPSTREAM_REQUEST_REJECTED
- 401/403：UPSTREAM_AUTH_FAILED
- 402：UPSTREAM_QUOTA_EXHAUSTED
- 429：UPSTREAM_RATE_LIMITED
- 5xx：UPSTREAM_UNAVAILABLE
- timeout：UPSTREAM_TIMEOUT
- DNS/连接失败：UPSTREAM_UNAVAILABLE

选择 DeepSeek 但缺少 DEEPSEEK_API_KEY 时返回 UPSTREAM_NOT_CONFIGURED。Gemini 与 DeepSeek 的 Key 检查互相隔离，未选择的 Provider 不会阻断当前模式。
