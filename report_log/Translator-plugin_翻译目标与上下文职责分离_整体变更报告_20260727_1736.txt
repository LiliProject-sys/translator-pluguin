2. 修改前行为

前端已经正确将用户选区作为 payload.text，并将自动提取上下文作为 payload.contextSentence。
Gateway body 也已经分别发送 text 和 contextSentence。
但是 Sentence Translation Prompt 只说明返回 translation/keyTerm，没有明确冻结：
- text / targetText 是唯一翻译目标；
- contextSentence 只能辅助理解；
- contextSentence 不得被翻译、复述、总结或输出；
- keyTerm.term 必须来自 targetText。

因此模型在 targetText 是短标题或短句、contextSentence 包含标题编号和下方正文时，可能把上下文中的额外内容也加入 translation。

3. 修改后行为

字段职责已在 JS Skill 与 Gateway Python Skill 中明确：
- text / targetText：用户实际选中的唯一 TARGET TEXT。
- contextSentence：CONTEXT ONLY，仅用于术语消歧、指代消解、省略内容理解、风格判断和背景理解。

translation 字段只能对应 targetText。
不得翻译、复述、总结或输出 contextSentence 中超出 targetText 的标题、编号、前后句、相邻段落或正文。
允许 contextSentence 消解 targetText 内部的术语、指代和省略，但不能增加 targetText 之外的独立内容。
keyTerm.term 必须来自 targetText；keyTerm.meaning 可以参考 contextSentence 判断含义。

7. skillVersion 与缓存依据

审计函数：
- gemini-context-provider.js:createCacheKey(input, model, skillVersion, analysisMode, requestType)
- deepseek-context-provider.js:createCacheKey(input, model, skillVersion, analysisMode, requestType)

缓存键包含：
- requestType
- analysisMode
- targetText
- contextSentence
- pageTitle
- model
- skillVersion

决策：
由于本地 Gemini / DeepSeek Provider 的 sentenceTranslation 结果缓存包含 skillVersion，若 Prompt 修改但 version 不变，同一个 service worker 生命周期内可能命中旧 Prompt 结果。因此本轮将 Sentence Translation Skill 升级为 sentence-translation-v1.1。

Gateway 路径当前没有客户端 sentenceTranslation 结果缓存，但 Gateway response 仍返回 skillVersion。升级版本有利于诊断和前后行为区分。
