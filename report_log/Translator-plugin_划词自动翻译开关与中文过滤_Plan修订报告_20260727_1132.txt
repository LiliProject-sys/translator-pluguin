3. 修改前与修改后

修改前 Plan 的不足：
- 主要覆盖已发出请求后的取消，没有完整覆盖 storage 初始化等待期间的旧选区任务；
- 页面刚加载时，英文 A 和英文 B 可能都等待同一个 settings Promise，resolve 后都继续执行；
- 浮窗内部 mouseup 如果被误判为新网页选区，可能破坏“加入生词本”“详细分析”、拖动、缩放等行为；
- Unicode property escape 如果用不当回退方式，旧环境可能在 JS 解析阶段直接失败；
- Popup set 失败时，如果 UI 已切到 nextValue，可能与真实 storage 状态不一致；
- 缺少 autoTranslateEnabled key 被删除后的默认开启行为说明；
- 对竞态和内部交互的测试计划不够完整。

修改后 Plan 的解决方式：
- 增加 selectionIntentId，任何 await autoTranslateSettingsPromise 后都检查 intent 是否仍是最新；
- 后一次选区会让前一次等待任务过期，前一次恢复后静默结束；
- 关闭开关时也递增 selectionIntentId，并复用 closeSelectionPanel() 取消已发请求；
- 保留 document mouseup 中现有 isEventInsideSelectionPanel(event) 与 panelPointerDown early-return；
- 中文过滤位于创建 snapshot、创建浮窗和发送 CHECK / TRANSLATE 之前；
- Popup 保存失败时恢复 previousValue、aria-checked、文案和可点击状态；
- storage 删除 key 时按 true 处理，但不自动处理残留选区；
- 新增专项竞态、回滚和内部 mouseup 测试计划。
