2. 修改前的行为

修改前，只要用户在普通网页中划选文本，content.js 的 document mouseup 监听会延迟调用 showPanelForCurrentSelection()。
如果选区非空并且可取得 Range，代码会立即创建 currentSelectionSnapshot、创建浮窗、发送 CHECK_VOCABULARY_STATUS 和 TRANSLATE_TEXT。
这意味着：
- 用户只是复制、搜索、临时选择文本，也会触发翻译；
- 中文网页或中英混合选区也会触发翻译；
- 用户无法在 popup 中临时关闭自动划词翻译；
- 如果新页面刚加载时设置还没读取完成，旧选区等待任务缺少请求发出前的 intent 保护。

3. 修改后的行为

Popup 现在有“划词自动翻译”开关。
默认开启，用户可以关闭；关闭后，网页划词不会自动弹出浮窗，也不会自动请求 Cloud Run。
开关状态保存在 chrome.storage.local 的 autoTranslateEnabled 中，重启浏览器或重新打开 popup 后仍保持。

content.js 现在会在发送任何自动翻译请求之前检查：
- autoTranslateEnabled 是否开启；
- selectedText 是否包含汉字。

如果开关关闭，或 selectedText 中包含汉字：
- 静默结束；
- 不创建翻译浮窗；
- 不发送 CHECK_VOCABULARY_STATUS；
- 不发送 TRANSLATE_TEXT；
- 不触达 Cloud Run；
- 不显示“检测到中文”等提示。

只检查 selectedText，不检查 contextSentence。
因此，如果用户只选中纯英文单词，但周围上下文有中文注释，仍允许翻译。

6. selectionIntentId 与旧请求处理

selectionIntentId 是本轮新增的请求发出前保护机制。
它的职责是防止以下竞态：
页面刚加载，storage.get 还没完成，用户先选英文 A，又马上选英文 B。A 和 B 都等待同一个 settings Promise 时，B 会递增 selectionIntentId；A 恢复后发现 intentId 已过期，直接 return，不创建浮窗、不发送 CHECK、不发送 TRANSLATE。

currentSelectionId / quick requestId / detail requestId 仍负责请求发出后的生命周期。
也就是说：
- selectionIntentId：保护发送请求前、异步等待设置阶段；
- currentSelectionId 和 requestId：保护已有 snapshot、已有浮窗、已有请求后的 stale response 丢弃。

用户关闭开关时：
- content.js storage listener 更新本页缓存；
- selectionIntentId += 1；
- closeSelectionPanel() 被调用；
- closeSelectionPanel() 清空 snapshot 和 requestId；
- 通过 cancelLanguageRequests() 发送 CANCEL_LANGUAGE_REQUEST；
- 等待中的旧任务和已发出的旧请求都会失效。

用户先划英文、再划中文时：
- 新中文选区会生成新的 intent；
- closeSelectionPanel() 使旧英文浮窗和请求失效；
- 检查 containsHanScript(selectedText) 后静默结束；
- 旧英文响应返回后会被现有 selectionId/requestId/snapshot 检查丢弃。

浮窗内部交互保护：
- document mouseup 仍先检查 isEventInsideSelectionPanel(event) 和 panelPointerDown；
- 如果是浮窗内部点击、按钮、拖动、缩放等操作，直接 return；
- 不会在这个 early-return 之前 closeSelectionPanel；
- 不会递增 selectionIntentId；
- 不会取消无关请求。

7. 中文选区过滤

汉字检测方式：
- 使用现代 Chromium 支持的 /\p{Script=Han}/u；
- 不引入第三方语言检测库；
- 当前只面向现代 Chrome/Edge。

过滤范围：
- 只检查用户实际选中的 selectedText；
- 不检查 contextSentence；
- selectedText 只要包含汉字就跳过。

实际效果：
- 纯中文选区跳过；
- 中英混合且含汉字选区跳过；
- 纯英文选区正常进入原链路；
- 含中文的上下文不会误拦截纯英文 selectedText。

拦截位置：
- 在 currentSelectionSnapshot = getSelectionContext() 之前；
- 在 createOrUpdateSelectionPanel() 之前；
- 在 checkCurrentSelectionStatus(selectionId) 之前；
- 在 requestTranslation(selectionId) 之前。

因此中文选区不会发送到 Cloud Run，也不会消耗 Gemini 请求额度。

10. 新发现 Bug：部分句子误走单词模式

状态：新发现、尚未修复的回归/边界问题。

现象：
划选有些完整英文句子或标题时，插件没有进入“句子翻译”模式，而是进入“单词/词组分析”模式，只选取其中一个词进行解释。
但另一些英文句子或段落能正常进入句子翻译模式。

异常例子：
选区：A Roadmap of Agent Research and Development
实际浮窗：按单词模式处理，单词显示为 roadmap，并给出音标、词性和“路线图；指导方针”。

正常例子：
选中论文 Abstract 的完整英文段落或句子时，实际浮窗按句子翻译模式处理，显示整段中文译文和关键词。

当前代码证据：
content.js 中模式判断函数是 detectSelectionRequestType(selectedText)，位置约 content.js:742-751。
当前判断条件是：
- 文本为空：wordAnalysis；
- 包含 . ? ! ;：sentenceTranslation；
- 单词数 > 10：sentenceTranslation；
- 字符数 > 80：sentenceTranslation；
- 其他：wordAnalysis。

异常标题 A Roadmap of Agent Research and Development：
- 无句号、问号、感叹号、分号；
- 约 6 个词，不超过 10；
- 字符数大概率不超过 80；
因此根据当前启发式，初步推测会被判为 wordAnalysis。

目前能确定：
- 最可能涉及 content.js 的 detectSelectionRequestType()；
- 标题或无句末标点的英文文本可能被当前启发式视作词组/短语；
- 本轮新增的中文过滤发生在 detectSelectionRequestType 之前，但它只影响含汉字 selectedText；
- 对纯英文标题，中文过滤不会触发；
- 本轮新增的 closeSelectionPanel / snapshot 顺序理论上不应改变 wordAnalysis 与 sentenceTranslation 的阈值判断。

目前不能确定：
- 浏览器实际 selection.toString() 是否完整包含整个标题；
- 是否页面 DOM / Range / selection 在某些标题上导致 selectedText 被截断；
- Gateway 收到的 text 与 requestType 是否与 content.js 判断一致；
- 是否还有其它函数在渲染时影响了显示词。

下一轮建议：
- 为 detectSelectionRequestType 增加专项测试，覆盖标题型文本；
- 用真实 selectedText 日志或安全调试方式确认标题选择时的实际 selectedText、wordCount、text.length、requestType；
- 讨论是否把英文标题型短文本也纳入 sentenceTranslation，例如首字母标题大小写模式、词数 >= 5 且无中文且非普通短语时判为句段翻译；
- 修复前不要直接打包给朋友作为最终体验版本，至少应记录该边界问题。
