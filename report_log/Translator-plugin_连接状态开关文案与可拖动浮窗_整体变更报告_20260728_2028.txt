Orange翻译 连接状态、开关文案与可拖动浮窗整体变更报告

1. 本轮基本信息

项目目录：D:\Project_Experimental\Translator_Plugin
当前分支：feat/gateway-beta
本轮目标：优化设置页连接状态提示、Popup 自动翻译开关文案与颜色、划词浮窗拖动体验。
本轮不涉及：Gateway、Cloud Run、Provider、Prompt、请求协议、response schema、Word Analysis、Sentence Translation、中文过滤、生词本数据结构、API Key、Token。

2. 修改前的问题

设置页中，Gateway 测试访问码验证成功后当前页面会显示“已连接，可以开始使用”，但重新打开设置页时只显示“已保存测试访问码”，不会恢复 gatewayStatus 的“已连接”提示，容易让用户误以为访问码丢失。

Popup 中，“划词自动翻译”开关只显示“开启 / 关闭”，语义可能被理解为点击后的动作，不够明确。

划词浮窗固定跟随选区附近出现，长译文或详细解释返回后可能遮挡正文。已有 resize 能调整大小，但不能把浮窗移动到用户希望的位置。

3. 修改后的用户行为

设置页重新打开后，如果本地保存了曾经验证成功的 Gateway 测试访问码，会恢复显示“已连接，可以开始使用”。设置页初始化不主动请求 Gateway。

Popup 自动翻译开关现在显示“当前已开启”或“当前已关闭”。开启态使用橙色强调，关闭态继续保持中性样式。

划词浮窗顶部新增六点拖动手柄。未拖动时仍靠近选区出现；用户拖动后，同一 content script 页面会话内继续划词、关闭后再次打开、翻译结果返回、错误状态、Detail 展开和内容尺寸变化时，浮窗都保持用户拖动后的位置并做视口边界校正。页面刷新、导航或标签页关闭后自然重置。

4. 设置页连接状态恢复方案

实际 storage key：translationSettings
实际访问码字段：translationSettings.gatewayAccessToken

代码检查确认，当前唯一主动写入 gatewayAccessToken 的用户路径是 options.js 中的 verifyGatewayAccessToken()。该函数先向 background 发送 TEST_LANGUAGE_PROVIDER，并由 Gateway Provider 调用验证接口；只有 response.status === "ok" 后才调用 writeSettings() 保存 gatewayAccessToken 和 provider: "gateway"。

因此本轮没有新增 verified 布尔字段，而是复用现有真实状态：gatewayAccessToken 非空表示本地保存了曾经验证成功的配置。该状态不代表每次打开设置页都实时连通 Gateway。

5. 新访问码验证失败时的处理

无旧连接时：
输入错误访问码并验证失败，不保存 token，不显示“已连接”，显示 Gateway 返回的错误文案或“测试访问码无效”。

有旧连接时：
输入新的错误访问码并验证失败，不覆盖旧 token，storage 中仍保留旧 gatewayAccessToken，页面显示“新访问码验证失败，原有连接仍可使用”。重新打开设置页后，会根据旧 token 恢复“已连接，可以开始使用”。

页面不会回显完整访问码，也不会把访问码写入日志。

7. 浮窗修改前 DOM、定位和交互

修改前，content.js 使用单个 #translator-plugin-selection-panel 外层 DOM，position: fixed。选区位置来自 Range.getBoundingClientRect()，由 positionSelectionPanel() 根据选区计算 left/top，并写入 currentPanelViewportPosition。

浮窗已有 ResizeObserver，尺寸变化后调用 keepSelectionPanelInViewport()。浮窗内容会通过 selectionPanel.innerHTML = "" 重建，但外层 panel 复用。

10. 用户拖动位置的保存范围

保存范围：当前 content script 页面会话内的模块变量。

保持位置：
同一页面继续划词；
浮窗关闭后再次划词；
翻译结果返回；
错误状态出现；
Detail 展开；
生词本状态变化；
页面滚动；
用户 resize 浮窗；
窗口 resize 后校正。

重置条件：
页面刷新；
标签页导航导致 content script 重新加载；
标签页关闭。

坐标不写入 chrome.storage.local 或 chrome.storage.sync。

11. 唯一坐标状态与视口边界算法

本轮只保留一套坐标来源：
currentPanelViewportPosition

hasUserPanelPosition 只表示当前坐标是否由用户拖动决定；isPanelDragging 只表示当前是否正在拖动。

未拖动时：
positionSelectionPanel() 按选区计算 currentPanelViewportPosition。

已拖动后：
positionSelectionPanel() 不再根据新选区重算位置，而是继续使用 currentPanelViewportPosition，并调用 clampPanelViewportPosition() 做边界校正。

keepSelectionPanelInViewport() 会把校正后的合法坐标写回 currentPanelViewportPosition，再调用 applyPanelViewportPosition()。因此窗口缩小、内容变高、Detail 展开、ResizeObserver 触发后，后续再次划词会保持校正后的新位置，不会回到旧的越界坐标。

12. 拖动阈值与 click 抑制

拖动阈值为 3px。

pointermove 中使用 Math.hypot(deltaX, deltaY) 判断移动距离。超过阈值后视为真实拖动，并设置 suppressNextPanelDragClick。拖动结束后的 click 会被 handlePanelDragClick() 阻止，避免误触发业务动作。

轻点手柄且几乎不移动，不会破坏浮窗。

13. 与 resize、ResizeObserver、重新渲染和 stale response 的兼容

拖动与 resize 互斥：只有顶部手柄启动拖动，正文、按钮、关闭、Detail、保存和原生 resize 区域不会启动拖动。

ResizeObserver 仍监听外层 panel，尺寸变化后继续调用 keepSelectionPanelInViewport()。浮窗内容重建时手柄会重新插入，拖动位置保存在模块变量中，不依赖旧 DOM。

stale response 仍由 currentSelectionId、currentQuickRequestId、currentDetailRequestId 和 snapshot identity 保护。拖动不改变这些请求生命周期字段。
