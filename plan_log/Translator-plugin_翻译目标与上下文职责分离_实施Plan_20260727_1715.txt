2. 根因定位

当前证据显示：
- content.js 正确把用户选区放入 payload.text。
- content.js 正确把自动上下文放入 payload.contextSentence。
- background.js 没有替换或拼接 text/contextSentence。
- gateway-language-provider.js 没有替换或拼接 text/contextSentence。
- Cloud Run schema 同时保留 text 和 contextSentence。
- 前端渲染只显示 response.translation。
- validator / normalizer 不会合并 context。

因此当前 bug 最可能发生在 Prompt 语义层：
- sentenceTranslation Prompt 没有明确冻结 text/targetText 是唯一翻译目标。
- contextSentence 作为辅助上下文存在，但 Prompt 未明确禁止翻译、复述、总结或输出 targetText 之外的上下文内容。
- 当 targetText 是短标题，例如 Definition of LLM Agent，而 contextSentence 包含标题编号和下方正文时，模型可能把 contextSentence 理解为也需要翻译的输入材料。

回答定位问题 12：
当前 bug 最可能发生在 Gateway 的 sentence_translation.build_prompt()，以及本地 sentence-translation-skill.js / Gemini / DeepSeek Prompt 的同类语义约束不足。

回答定位问题 13：
可以用测试稳定复现“请求构造层没有混字段”和“Prompt 是否包含强约束”。
模型真实输出越界本身不适合依赖外部 API 做稳定自动化，但可以通过固定 Mock 响应和 Prompt 文本断言覆盖防线。

回答定位问题 14：
优先不改公开协议。
现有 text/contextSentence 字段语义足够，采用方案 A：
- text -> TARGET TEXT / selectedText / 唯一主目标
- contextSentence -> CONTEXT / 辅助语境
主要修 Prompt 与测试。
不建议在本轮新增 targetText/contextText 字段，除非实现时发现 Cloud Run schema 或 Provider 约束无法表达该语义。

3. 冻结后的产品规则

核心规则：
用户实际选中的文本始终是唯一的分析或翻译目标；自动提取的上下文只能帮助理解，不能扩大输出范围。

字段职责：
- text / targetText / currentSelectionSnapshot.word：唯一主目标。
- contextSentence：辅助语境。

wordAnalysis：
- text / targetText 是要分析的单词或连续词项。
- contextSentence 只用于判断该词在当前句子中的含义。
- 输出必须只解释 targetText。

sentenceTranslation：
- text / targetText 是唯一翻译对象。
- contextSentence 只用于术语消歧、指代消解、风格判断和理解背景。
- 即使 contextSentence 包含标题编号、前一句、后一句、整段正文或相邻章节内容，也不得把超出 text / targetText 的内容加入译文。

4.4 gateway/app/skills/sentence_translation.py

这是本轮核心修改文件。

建议语义：
- request.text 是 TARGET TEXT，是唯一需要翻译的内容。

- 只翻译 TARGET TEXT。

- targetText: request.text
- contextSentence: request.context_or_text()
- pageTitle
- sourceLanguage
- targetLanguage

如需最小增强，可将 user JSON 字段名改为更明确但仍只在 Gateway 内部 prompt 中使用的结构：
- TARGET_TEXT: request.text
- CONTEXT: request.context_or_text()

12. 给 ChatGPT 的快速上下文

当前 bug 不是多词短语模式判断问题。
多词短语和短标题已经进入 sentenceTranslation。

当前问题是 sentenceTranslation 输出范围错误：
- 用户只选中标题、句子或段落。
- content.js 的浮窗标题显示 selectedText 正确。
- 但模型输出可能包含 contextSentence 中的相邻正文或标题编号。

真实链路审计结论：
- content.js：selectedText 存在 snapshot.word，context 存在 snapshot.contextSentence。
- TRANSLATE_TEXT：payload.text 是 snapshot.word，payload.contextSentence 是 snapshot.contextSentence。
- background.js：没有混字段。
- gateway-language-provider.js：Cloud Run body 同时发送 text 与 contextSentence，没有拼接。
- gateway/app/schemas.py：LanguageRequest 同时有 text 和 contextSentence。
- gateway/app/skills/sentence_translation.py：user JSON 有 targetText/contextSentence，但 system Prompt 没有强约束“只翻译 targetText”。
- sentence-translation-skill.js、本地 Gemini、DeepSeek Prompt 也缺少同类硬约束。
- validator / normalizer 不会合并 context。
- 前端只渲染 response.translation。

最小修复方向：
不改协议，采用方案 A。
冻结字段语义：
- text / targetText = TARGET TEXT = 用户实际选中的唯一处理目标。
- contextSentence = CONTEXT = 仅辅助理解，不得被翻译、复述、总结或输出。

主要修改 Prompt 与测试。
如果修改 Cloud Run Gateway 的 Python Skill，需要重新部署 Cloud Run 才会影响 Gateway Beta 真实用户。
